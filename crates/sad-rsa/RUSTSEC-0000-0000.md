# Panic in RSASSA-PSS verification with automatic salt length on small public keys

RSASSA-PSS signature verification can panic when the salt length is detected from the signature
and the public key is too small for the hash function.

This affects verification through `pss::VerifyingKey::new_with_auto_salt_len`, and through
`RsaPublicKey::verify` with a `Pss` whose `salt_len` is `None`. Verification with a fixed salt
length is not affected. PKCS#1 v1.5 signatures, encryption and decryption are not affected.

The panic happens when the modulus is at most `8 * hLen + 9` bits, where `hLen` is the output
size of the hash in bytes: 521 bits with SHA-512, 393 bits with SHA-384, 265 bits with SHA-256.
The attacker needs to supply the public key and a signature whose encoded message ends in the
byte `0xBC`. No private key is needed.

An application that verifies PSS signatures with automatic salt length against public keys it
does not control, and that does not enforce a minimum key size, can lose a worker, or the whole
process when built with `panic = "abort"`.

Fixed in 0.10.6, where verification returns an error when the encoded message is too short to
hold the hash.

If you cannot upgrade, reject public keys with a modulus below 1024 bits before verifying, or
verify with a fixed salt length, or wrap verification in `catch_unwind` when panics unwind.
