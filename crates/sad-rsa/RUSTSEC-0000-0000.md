# Timing side channel in RSA decryption: time depends on the leading zero bytes of the decrypted value

After the RSA private-key operation, decryption converted the result to bytes by skipping its
leading zero bytes and copying the rest into a buffer of the modulus size. The number of bytes
copied, and the offset they were copied to, depended on how many leading zero bytes the decrypted
value had. That value is secret.

This affects OAEP and PKCS#1 v1.5 decryption, with and without blinding. Blinding does not help,
because the conversion happens after the result is unblinded. Signing and signature verification
are not affected.

Whether the decrypted value starts with zero bytes is the information that Manger's attack on
OAEP and Bleichenbacher-style attacks on PKCS#1 v1.5, including the Marvin attack, are built on.

The difference is measurable. With the Marvin toolkit at 200 million repetitions per class
(RSA-2048, measured inside the decrypting process), 0.10.5 takes about 11 ns longer, on a 1.09 ms
operation, to decrypt a ciphertext whose decrypted value starts with 208 zero bytes than any
other class tested. No exploit is known, and the difference has not been demonstrated over a
network. Classes with one leading zero byte and with none did not differ from each other in the
same run.

Fixed in 0.10.6, where the conversion always copies the same number of bytes from the same
offset. There is no workaround in the library; limiting how many decryptions a peer can request
with one key reduces the number of measurements an attacker can take.
